# Corvia backend

The Anthropic API key and the scan-credit balance live here, not in the app.

## Run it

```bash
cd backend
python -m venv .venv
.venv/Scripts/activate          # Windows;  source .venv/bin/activate on macOS/Linux
pip install -r requirements-dev.txt

cp .env.example .env            # fill in your keys
uvicorn corvia.app:app --reload --host 0.0.0.0 --port 8000
```

`--host 0.0.0.0` matters for development: the app runs on a phone, not on your
machine, so it needs to reach your laptop over the LAN.

## Tests

```bash
python -m pytest          # 69 tests
```

## Mounting on the existing Corvia backend

Preferred — you already serve `/auth/*` there, and these routes need that JWT.

```python
from corvia.routers import screening_router, wallet_router, payment_router

app.include_router(screening_router, prefix="/api/v1")
app.include_router(wallet_router,    prefix="/api/v1")
app.include_router(payment_router,   prefix="/api/v1")
```

Then replace `corvia/auth.py`'s `current_user` with your own dependency; it only
needs to return an object with `.id` and `.email`. It refuses every request
until you do — a service that ships with auth accidentally disabled is worse
than one that fails loudly.

## What each module is for

| File | Role |
|---|---|
| `corvia/routers.py` | The HTTP routes. Enforces "never charge for a screening the user did not receive". |
| `corvia/analysis.py` | The only place the Anthropic key is used. |
| `corvia/gateway.py` | Flutterwave. `verify_webhook_signature` is the entire access control on the webhook. |
| `corvia/store.py` | Wallets, transactions, payments. **Replace with your database** — keep the locking and idempotency properties. |
| `corvia/schemas.py` | Request validation. Clients send symptom ids, never free text. |
| `corvia/config.py` | Settings and the symptom library. |
| `symptoms.json` | Generated by `npm run export:symptoms`. Do not hand-edit. |

## Before production

`store.py` is in-memory: it forgets everything on restart and does not work
across more than one worker process. It is the right *shape* — per-user locking
and idempotent crediting — but the storage must become real. In SQL,
`wallet_lock` is `SELECT ... FOR UPDATE` inside a transaction.

The rest of the checklist is in [`../BACKEND.md`](../BACKEND.md).
